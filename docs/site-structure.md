# Site structure, sections and editorial conventions

## Human, agent and machine interfaces

| Interface | Address | Status |
| --- | --- | --- |
| Human | [aipel.co.uk](https://aipel.co.uk/) — Hub, Engineering, Academy, Frontiers | available |
| Agent | [`aipe.md`](https://aipel.co.uk/aipe.md) — public, agent-readable Registry interface | available |
| Agent | AIPE Plugin — installable agent integration ([architecture note](aipe-plugin-architecture.md)) | planned |
| Machine | [`aipe.json`](https://aipel.co.uk/aipe.json) — machine-readable Registry index | available |

Give a compatible coding agent this URL:

```text
https://aipel.co.uk/aipe.md
```

The index is generated by AIPE Registry from validated capability manifests and states each capability's type, maturity, integration, limitations and canonical repository. It is a public index, not an executable model or application.

## Website content

The header has four items — Hub, Academy and Frontiers, each a link to its landing page with a dropdown (Hub and Academy list their subsections; Frontiers lists Frontiers and the Blog article library at `/resources/blog/`), and Plugin as a direct link — plus the globe language menu and the Contact Us button. Each landing page also organises its subsections with in-page tabs. The footer keeps the multi-column layout with Hub (Data & Models, Tools & Agents, Workflows), Learn & Explore (Academy, Frontiers, Plugin), Company (About, News, Contact) and Legal (Privacy, Terms, Cookies) columns.

- **Hub** (`/hub/`) — an overview of three categories, each with its own page: Data & Models, Tools & Agents and Workflows. Each page shows minimal project cards (name, short summary, status while in development, links) for the artifacts in `_data/hub.yml` that carry a `card`; detailed metadata stays in the Registry. Teaching netlists, scripts and labs are presented in the Academy. The former `/hub/models/`, `/hub/designs/` and `/hub/labs/` URLs redirect.
- **Engineering** (`/engineering/`) — the same artifacts by domain: Devices, Magnetics, Converters, Control, Energy Storage, Microgrids and Energy Systems, plus the in-depth domain pages under `/power/`.
- **Academy** (`/academy/`, `/zh/academy/`) — an engineering knowledge platform with the four canonical AIPE Academy domains (Foundations, Power Electronics, Power Systems, Renewable Energy), each with its own page (`/academy/<domain>/`) showing a short introduction, its part of the interactive engineering knowledge graph, available lessons and practical resources. The graph is an explorable network in the style of the Blog knowledge map (rotate, zoom, select a topic for its prerequisites, related topics and lessons), drawn by one shared engine for the Academy home and every subject page. Lessons, topics, prerequisites and academic references are published from a pinned AIPE Academy revision (`tools/sync_ecosystem.py`); each page lists only lessons in its own language, topics without a lesson are shown as planned, and every lesson page links its canonical GitHub source, lab scripts and external MIT OpenCourseWare references. The graph data (`_data/knowledge_graph.yml`) is generated from the Academy; the website adds only its own links per topic in `_data/knowledge_graph_resources.yml`. English subject pages live in `academy-subjects/` so the generated `academy/` folder stays untouched; the former `/academy/renewables/` URL redirects to `/academy/renewable-energy/`.
- **Frontiers** (`/frontiers/`, `/zh/frontiers/`; formerly Explorations, whose URLs redirect) — emerging concepts and open research questions shown as topic cards, each labelled with an evidence status (Concept to Experimentally validated, or Refuted) that the build checks against its recorded evidence, so hypotheses are never presented as results. Entries live in `_explorations/` and follow [exploration-template.md](exploration-template.md).
- **Team** (`/company/team/`, `/zh/company/team/`) — the human team and the digital team of specialist agents, rendered from `_data/team.yml`; each agent states its development status and links only to a repository that exists.
- **Articles and news** — engineering articles (`/resources/blog/`) and news (`/news/`). Articles are classified LEARN, RESEARCH, BUILD or NEWS and move to their destination in reviewed waves; see [content-migration-map.md](content-migration-map.md).
- **AIPE Plugin** (`/plugin/`) — the unified entry point (today a capability-discovery prompt for `aipe.md`; installation and orchestration are planned) and Standalone Plugins cards for each agent in `_data/agents.yml`. Each agent has a detail page under `/resources/ai-agent-team/` built from the shared `agent` layout. Implementation detail stays in [aipe-plugin-architecture.md](aipe-plugin-architecture.md).
- **English and Chinese pages** — mirrored navigation and content. English pages are English-only and Chinese pages Chinese-only (product names and technical abbreviations excepted); the language switch, not inline bilingual content, selects the language.
- **Public vs developer content** — public pages describe capabilities and outcomes. Internal architecture (Registry, Core, routing, synchronization) and the `aipe.md` / `aipe.json` interfaces are documented here and linked from the Plugin FAQ, not the main navigation or footer.

## Project structure

```text

├── _posts/          Engineering articles and project updates

├── academy-subjects/ English Academy subject pages (site-owned presentation)
├── accessories/     Published engineering reference assets
├── assets/          Stylesheet, Hub script, article figures, circuits, downloads
├── company/         About, team, careers, and FAQ pages

├── frontiers/       Frontiers landing page
```

Source directories mirror the final public URL hierarchy. Existing public links under superseded paths such as `/case-studies/` are retained through the files in `legacy/`.

## Language and editorial conventions

English copy uses British English. Public navigation labels, page titles, URL paths, and cross-language links should remain aligned across the English and Chinese versions.

Blog articles live in `_posts/` (English) and `_posts/zh/` (Chinese). A translated article should use the same filename slug as its source and set `lang: zh`; the layouts then discover the matching article automatically and render language-switch and `hreflang` links. If matching slugs are not possible, give both files the same `translation_key`. Keep series navigation in the shared files under `_includes/` rather than duplicating it inside articles.

Generated build output (`_site/`, `.jekyll-cache/`), local dependencies (`vendor/`, `.bundle/`) and scratch output (`output/`) are ignored. Public assets belong in `assets/`, `images/` or `accessories/`; one-off generation utilities belong in `tools/` and are excluded from the published site.
