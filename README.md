AIPE — **AI for Power Engineering** — is the open engineering platform for power and energy, built around three complementary parts: **Learn** established knowledge in AIPE Academy, **Build** with reusable data, models, designs, tools and labs in AIPE Hub, and **Explore** open research questions in AIPE Explorations. *Learn what we know. Build what we need. Explore what we don't yet know.*

This repository is the human-facing presentation layer of that ecosystem (`aipe.presentation`). It publishes [aipel.co.uk](https://aipel.co.uk/) and the Registry's agent- and machine-readable endpoints. It does not implement the databases, agents or tools themselves; each lives in its own repository and stays the source of truth.

## Human, agent and machine interfaces

| Interface | Address | Status |
| --- | --- | --- |
| Human | [aipel.co.uk](https://aipel.co.uk/) — Hub, Engineering, Academy, Explorations | available |
| Agent | [`aipe.md`](https://aipel.co.uk/aipe.md) — public, agent-readable Registry interface | available |
| Agent | AIPE Plugin — installable agent integration ([architecture note](docs/aipe-plugin-architecture.md)) | planned |
| Machine | [`aipe.json`](https://aipel.co.uk/aipe.json) — machine-readable Registry index | available |

Give a compatible coding agent this URL:

```text
https://aipel.co.uk/aipe.md
```

The index is generated by AIPE Registry from validated capability manifests and states each capability's type, maturity, integration, limitations and canonical repository. It is a public index, not an executable model or application.

## Website content

The header has four direct links — Hub, Academy, Explorations and Plugin — plus the EN / 中文 switch, with no dropdown menus. Each landing page organises its own subsections with in-page tabs. The footer links the same four sections, About, News and Contact, and the legal pages.

- **Hub** (`/hub/`) — engineering artifacts by type: Data, Models, Designs, Tools & Agents and Labs, rendered as artifact cards from Registry data and filterable by engineering domain.
- **Engineering** (`/engineering/`, linked from the Hub tabs) — the same artifacts by domain: Devices, Magnetics, Converters, Control, Energy Storage, Microgrids and Energy Systems, plus the in-depth domain pages under `/power/`.
- **Academy** (`/academy/`, `/zh/academy/`) — a staged learning path and open labs, published from a pinned AIPE Academy revision. Each entry point lists only lessons in its own language.
- **Explorations** (`/explorations/`, `/zh/explorations/`) — open research questions and investigations, each labelled with an evidence status (Concept to Experimentally validated, or Refuted) that the build checks against its recorded evidence. Entries live in `_explorations/` and follow [docs/exploration-template.md](docs/exploration-template.md).
- **Articles and news** — engineering articles (`/resources/blog/`) and news (`/news/`). Articles are classified LEARN, RESEARCH, BUILD or NEWS and move to their destination in reviewed waves; see [docs/content-migration-map.md](docs/content-migration-map.md).
- **AIPE Plugin** (`/plugin/`) — what coding agents can do with AIPE, how to use it today and the planned installable plugin. Implementation detail stays in [docs/aipe-plugin-architecture.md](docs/aipe-plugin-architecture.md).
- **English and Chinese pages** — mirrored navigation and content. English pages are English-only and Chinese pages Chinese-only (product names and technical abbreviations excepted); the language switch, not inline bilingual content, selects the language.
- **Public vs developer content** — public pages describe capabilities and outcomes. Internal architecture (Registry, Core, routing, synchronization) and the `aipe.md` / `aipe.json` interfaces are documented here and linked from the Plugin FAQ, not the main navigation or footer.

## Local development

The site is built with Jekyll and is compatible with GitHub Pages.

```bash
bundle install
bundle exec jekyll serve
```

Then open `http://localhost:4000/`.

## Language and editorial conventions

English copy uses British English. Public navigation labels, page titles, URL paths, and cross-language links should remain aligned across the English and Chinese versions.

Blog articles live in `_posts/` (English) and `_posts/zh/` (Chinese). A translated article should use the same filename slug as its source and set `lang: zh`; the layouts then discover the matching article automatically and render language-switch and `hreflang` links. If matching slugs are not possible, give both files the same `translation_key`. Keep series navigation in the shared files under `_includes/` rather than duplicating it inside articles.

Generated build output (`_site/`, `.jekyll-cache/`), local dependencies (`vendor/`, `.bundle/`) and scratch output (`output/`) are ignored. Public assets belong in `assets/`, `images/` or `accessories/`; one-off generation utilities belong in `tools/` and are excluded from the published site.

Before publishing, run:

```bash
python tools/sync_ecosystem.py --check
python tools/hub_data.py --check
python tools/content_data.py --check
python -m unittest discover -s tests -v
bundle exec jekyll build --trace
python tools/check_public_build.py _site
python tools/check_site_links.py _site
git diff --check
```

Hub cards never restate Registry metadata. To add a capability to the site, refresh the Registry snapshot, run `python tools/hub_data.py --write`, and place the new ID in `_data/hub.yml`. See [Hub presentation data](docs/ecosystem-v0.1.md#hub-presentation-data).
